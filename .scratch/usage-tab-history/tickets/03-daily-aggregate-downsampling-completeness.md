# 03 — Daily aggregate: storage, downsampling job, completeness, gap detection, API

**What to build:** A new `usage_daily` table with the full field set from the spec — two-snapshot model (trigger-moment + day-total for all ambient signals including concurrency), two-dimension activity (Dimension A accumulated active minutes + Dimension B UTC clock span), per-hour activity map, degradation burden, static-for-day limits. A downsampling job runs at proxy startup + once per UTC-midnight crossing: finds UTC days older than `usage_raw_retention_days` lacking a daily row, computes the aggregate, writes it, deletes the raw samples. A `day_completeness` detector classifies each day (full/partial_start/partial_end/partial_both/missing/incomplete_window) with gap detection via `usage_gap_threshold_minutes`. Both config knobs hot-reloadable. A new `GET /dashboard/api/usage/daily?from=&to=` endpoint returns daily rows. Run the proxy across a UTC midnight → see raw samples collapse into one daily row; stop/restart with a multi-day gap → see `missing` and `partial_*` days backfilled. This slice is what keeps the app user-scale (~10 MB/year) and makes long-term pattern analysis possible.

**Blocked by:** 02 — Events (daily aggregate needs event counts, ban durations, and trigger-moment ambient snapshots from the events table)

**Status:** ready-for-agent

- [ ] `usage_daily` table created at startup via `CREATE TABLE IF NOT EXISTS`, gated on `usage_history_enabled`. Primary key `utc_date` ('YYYY-MM-DD').
- [ ] Field set per spec: `day_completeness`; Dimension A (`active_minutes`, `active_minutes_by_utc_hour` JSON 24-bucket); Dimension B (`activity_span_minutes`, `first_activity_utc_hour`, `last_activity_utc_hour`); day-total (tokens_*_total, requests_*, cache_hit_rate_avg, concurrent_sessions_*); trigger-moment (`at_first_priority_event` JSON, `at_first_service_mode_event` JSON, both NULL if no event of that kind that day); degradation burden (priority_low_minutes, boxed_minutes, units_demoted_minutes, service_mode_non_normal_minutes, priority_events_count, service_mode_events_count, priority_ban_total_duration_ms, service_mode_ban_total_duration_ms); static-for-day (concurrency_hard_cap, requests_limit, requests_hard_cap).
- [ ] Downsampling job: runs once at startup, then `setTimeout` to next UTC 00:00:00, then `setInterval` at 24h. Idempotent — "find dates lacking a daily row" is safe to run repeatedly.
- [ ] Job logic per UTC day: query `usage_samples` for that date. If no samples → write row with `day_completeness = "missing"` and NULL activity fields. If samples exist → compute aggregate, detect completeness (first sample's UTC hour > 0 → `partial_start`; last sample's UTC hour < 23 → `partial_end`; both → `partial_both`; mid-day gaps > `usage_gap_threshold_minutes` with non-identical adjacent rows → `incomplete_window`; otherwise → `full`). Insert daily row. Delete raw samples for that date. Events are never touched.
- [ ] Gap detector: a gap counts as incomplete only when `next_sample.fetched_at − prev_sample.fetched_at > threshold` AND the adjacent samples are NOT byte-identical (idle-coalesce gaps don't count).
- [ ] Config knobs `usage_raw_retention_days` (default 7, hot-reloadable, integer ≥ 1) and `usage_gap_threshold_minutes` (default 60, hot-reloadable, integer ≥ 5) added to config pipeline.
- [ ] `GET /dashboard/api/usage/daily?from=YYYY-MM-DD&to=YYYY-MM-DD` returns daily rows for the range.
- [ ] Integration test — multi-day scenario across UTC midnight: drive mock upstream through day N + day N+1; trigger downsampling (or simulate time advance); fetch `/daily` → assert day N has a daily row with correct two-snapshot fields, Dimension A/B activity, and `day_completeness = "full"`; assert raw samples for day N are pruned; assert day N+1 (still within retention) retains raw samples.
- [ ] Integration test — self-healing: stop proxy at T0, restart at T0+3days; assert `day_completeness = "partial_end"` for the stop day, `"missing"` for the gap days, `"partial_start"` for the restart day.
- [ ] Integration test — gap detection: drive a 90-minute gap with non-identical adjacent snapshots → assert `day_completeness = "incomplete_window"`; drive a 90-minute gap with byte-identical adjacent snapshots → assert `day_completeness = "full"` (coalesce gap, not incompleteness).
- [ ] `bun run typecheck` passes; `bun run lint` clean; no type suppressions.
